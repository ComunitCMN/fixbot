# Прочти это первым

Проект живой: два бота работают на сервере с настоящими агентствами
и настоящей amoCRM застройщиков. Ошибка здесь стоит не «упавшего теста»,
а потерянной фиксации у живого агента.

Владелец проекта — не программист. Он не прочитает код и не заметит,
если поведение тихо изменится. Проверять должен ты.

## Порядок в начале разговора

1. `РЕШЕНИЯ.md` — что решено и **почему**. Каждое решение закреплено
   тестом. Ломается тест из этого списка — значит правка отменяет
   решение, а не «тест устарел».
2. `README.md` — устройство кода.
3. `СЕРВЕР.md` — как всё устроено на сервере.
4. `БЕЗОПАСНОСТЬ.md` — порядок выкатки и откат. Владелец работает
   по нему; не предлагай ему `git pull` и `systemctl restart` руками,
   на сервере для этого есть `обновить.sh` с автоматическим откатом.

## Чего делать нельзя

**Не спрашивай ключи, токены и пароли.** Никогда. Владелец вписывает их
сам в `.env` на своей машине и на сервере. Если он прислал секрет
в переписку — скажи отозвать и перевыпустить.

**Не коммить `.env`, `clients/*/.env`, `*.db`, `*.log`.** Они в
`.gitignore`. Перед первой отправкой в новый репозиторий проверь
историю: `git log --all --name-only --diff-filter=A | grep -E '\.env$'`.

**Не правь код на сервере руками.** Только `git pull`. Иначе сервер
и репозиторий разъедутся, и никто не вспомнит, где правда.

**Не отменяй мягкий тон.** Бот никогда не говорит агенту «работать
нельзя». Он сообщает факт и отправляет к менеджеру.

**Не показывай агентам amoCRM.** Ни ссылок, ни слова «CRM», ни названий
конкурирующих агентств — только даты.

**Не добавляй уведомлений.** Их ровно четыре, список в `РЕШЕНИЯ.md`.
Просьба «а давай ещё про смену этапа» уже была отклонена.

**Не трогай деньги без оператора.** Счёт клиенту уходит только по его
нажатию. Автоматически — лишь объявление о начале периода и одно
напоминание. Приостановка невозможна, пока счёт не отправлен.

**Не пиши агентам про оплату.** Отношения оператора с застройщиком их
не касаются: приостановленный бот отвечает нейтрально.

**Не отдавай вердикт незнакомцу.** «Клиент у отдела продаж» — это
сведения о базе застройщика. В личке отвечаем по существу только тем,
кого бот знает; правило в `access.py`.

## Как вносить изменения

Сначала тест, потом код. Тест должен падать до правки — иначе он ничего
не проверяет.

Прогон: `python -m pytest -q` из корня. Должно быть **всё зелёное**;
на момент последней правки — 621 тест. Падает хоть один — не отдавай
работу.

Владельцу вместо этого хватает `./проверить.sh` — тот же прогон, но
ответ одним словом.

Тесты не должны требовать `.env`: `conftest.py` подставляет заглушки,
чтобы они шли и на чистом сервере, и без боевых ключей.

## Границы предметной области

Это фиксация клиентов агентствами у застройщика. Ключевое, что ломают
чаще всего:

- **агентская фиксация не даёт эксклюзива** — совпадение с чужой
  агентской фиксацией не блокирует, ответ зелёный «работайте»;
- **блокирует только прямой отдел продаж**, и то освобождается через
  год без активности;
- **телефоны приходят с закрытыми цифрами** — сравнение идёт по
  известной части, до двух скрытых цифр включительно;
- **в CRM ничего не пишется без нажатия кнопки** агентом. Именно
  поэтому распознавание намеренно «свободное».

## Данные

Копии уезжают с сервера ежедневно, зашифрованными, в Telegram
владельцу (`backup.sh`). Восстановление — `restore-on-server.sh`,
сценарий в `ВОССТАНОВЛЕНИЕ.md`, проверен на учебной тревоге.

Если трогаешь схему базы — добавь миграцию в `MIGRATIONS` в `db.py`.
Базы на сервере уже с боевыми данными, пересоздать их нельзя.

## Что делается прямо сейчас

Хвост в конце `РЕШЕНИЯ.md`: фиксация в личке, частные агенты, переход
между агентствами. Решения приняты, `access.py` написан и покрыт
тестами, остальное — нет. Начинать с закрытия `/check`: он сегодня
отвечает кому угодно.
