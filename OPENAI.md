# Переход FixBot на OpenAI API

Проверка фиксаций и перевод рассылок переведены на OpenAI Responses API.
Модель закреплена: `gpt-5.4-mini-2026-03-17`, `reasoning.effort=none`.
Это короткая проверка с прежними лимитами: 500 токенов / 30 секунд для
фиксации, 4000 токенов / 45 секунд для перевода. Новых зависимостей нет:
используется уже установленный `httpx`.

## Настройки перед запуском

1. Создайте ключ в [кабинете OpenAI](https://platform.openai.com/api-keys).
   Ключ вписывайте только в `.env`, не в переписку и не в `.env.example`.
2. В существующий `.env` оператора и **каждого** действующего клиента
   добавьте две строки. Вместо `ваш_ключ` впишите настоящий ключ:

   ```dotenv
   OPENAI_API_KEY=ваш_ключ
   OPENAI_MODEL=gpt-5.4-mini-2026-03-17
   ```

   На маке операторский файл — `~/Desktop/fixbot/.env`, клиентские —
   в папке клиентов, указанной в `CLIENTS_DIR` (обычно `~/Desktop/clients/<клиент>/.env`).
   На сервере — `/opt/fixbot/app/.env` и `/opt/fixbot/clients/<клиент>/.env`.
   Достаточно настроить файлы там, где вы запускаете ботов; перед
   серверным обновлением серверные файлы должны быть готовы.
3. Остальные строки оставьте как есть, включая `MIN_CONFIDENCE`.
   Не заменяйте существующий `.env` целиком примером: в нём токены
   Telegram и amoCRM, настройки воронок и пути к данным.
4. **Сохраните старые `ANTHROPIC_API_KEY` и `MODEL` для отката.**
   Новая версия ключ Claude не читает. `OPENAI_MODEL` приоритетнее
   `MODEL`. Если новая модель не задана, старое значение `MODEL=claude-*`
   автоматически заменяется моделью OpenAI по умолчанию. Значение
   `MODEL` с моделью OpenAI продолжает работать.

Помощник подключения наследует `OPENAI_API_KEY` и `OPENAI_MODEL` от
оператора новым клиентам. Уже созданным клиентам он настройки не меняет.
Без нового ключа запуск остановится с сообщением «Укажите OPENAI_API_KEY».

## Проверка и обновление

На маке, из папки проекта:

```bash
./проверить.sh
```

После зелёной проверки сохраните код обычным способом:

```bash
./сохранить.sh "перевод проверки фиксаций и рассылок на OpenAI API"
```

После заполнения `.env` на сервере, из `/opt/fixbot/app`:

```bash
./обновить.sh
```

Порядок выкатки и автоматический откат остаются прежними —
[БЕЗОПАСНОСТЬ.md](БЕЗОПАСНОСТЬ.md). Отдельный `git pull` и ручной
перезапуск служб не нужны.

После обновления отправьте в рабочий чат выдуманные имя и телефон.
Должна появиться прежняя карточка с кнопкой. Для проверки только API
кнопку нажимать не нужно. Отдельно посмотрите превью английского
перевода рассылки. Проверка на реальном API нужна после ввода ключа:
автотесты используют заглушки и не подтверждают доступность модели
для конкретного аккаунта или качество распознавания живых сообщений.

## Что сохранено

- `prompts/fixation.md` и промпт перевода — без изменений.
- Предфильтр, контекст автора, поля результата и порог уверенности.
- Работа с номерами, правила уникальности, кнопки подтверждения,
  amoCRM, данные, биллинг, доступы, уведомления и скрипты выкатки.
- При ошибке API фиксация не создаётся, как раньше.
- Оборванный или отклонённый перевод не отправляется: остаётся прежний
  переход к оригиналу (или репосту — по выбранному режиму рассылки).

Для классификации задана строгая JSON-схема с прежними полями.
Неполные ответы и отказы модели отбрасываются. В оба запроса передаётся
`store=false`; сырой ответ с именем и телефоном не пишется в лог при
ошибке разбора. `store=false` не равнозначно отключению всех журналов
на стороне провайдера — условия описаны в
[документации о данных API](https://developers.openai.com/api/docs/guides/your-data).

Формат запроса сверён с официальной документацией:
[модель](https://developers.openai.com/api/docs/models/gpt-5.4-mini),
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).
