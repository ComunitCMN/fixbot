# FixBot — фиксация клиентов из Telegram в amoCRM

Бот сидит в рабочих чатах, через Claude понимает, что перед ним фиксация
клиента, определяет **чей это клиент**, и заводит его в amoCRM с привязкой
к агентству.

## Главное правило

**Агентская фиксация не даёт эксклюзива.** Несколько агентств могут вести
одного клиента одновременно — он достаётся тому, кто первым доведёт до
брони. Поэтому совпадение с чужой агентской фиксацией не блокирует.

**Блокирует только клиент отдела продаж** — тот, кто пришёл по рекламе,
звонком или с сайта. Определяется по воронке связанной сделки.
Освобождается после года без активности.

## Восемь сценариев ответа

| | Ситуация | Ответ | Фиксируем |
|---|---|---|---|
| 🟢 | совпадений нет | клиент уникальный | да |
| 🟢 | чужая агентская фиксация | «работайте, кто первым приведёт под депозит» | **да** |
| 🟢 | розница без движения > года | клиент освободился | да, + уведомление админу |
| ℹ️ | вы же и фиксировали | напоминание | нет |
| ℹ️ | коллега из вашего агентства | «уже зафиксировал X» | нет |
| 🟡 | контакт есть, истории нет | «нужна проверка», уходит менеджеру | нет |
| 🔴 | клиент отдела продаж | «уточните у своего менеджера» | нет |
| 🔴 | уже на брони у другого | то же | нет |

Агентская фиксация **не даёт эксклюзива** — несколько агентств ведут
клиента параллельно. Название конкурента при этом не раскрывается,
только дата.

## Подтверждение кнопкой

Бот ничего не пишет в CRM сам. Он показывает карточку с разобранными
данными и вердиктом, а записывает только после нажатия «✅ Зафиксировать».
Нажать может лишь автор сообщения.

Из-за этого порог распознавания намеренно низкий (`MIN_CONFIDENCE=0.3`):
лишний вопрос стоит одного проигнорированного сообщения, а пропущенная
фиксация — потерянного клиента.

На карточке можно дописать имя клиента или сменить агентство. Карточка,
которую никто не подтвердил, снимается через час.

## Неполные номера

Агентства пишут номер без последних цифр. Правило: **скрытыми можно
оставить максимум две последние**. Сколько это в цифрах — зависит от
страны.

| Написано | Известно | Что делает бот |
|---|---|---|
| `+7 999 123-45-67` | 11 из 11 | точное совпадение |
| `+7 999 123-45-6*` | 10 из 11 | поиск по совпадающей части |
| `+7 999 123-45-**` | 9 из 11 | то же |
| `+7 999 123-4*-**` | 8 из 11 | **отказ**, просит дописать цифру |

Сравнение симметричное: в CRM лежит маскированный, пришёл полный (или
наоборот) — совпадение найдётся. Понимаются `**`, `xx`, `хх`, `__`, `??`,
`...` и местные записи вроде `8 999…`.

## Любые страны

Разбором занимается libphonenumber. Своих таблиц кодов нет, поэтому
работают Россия, Индонезия, ОАЭ, Турция, Таиланд, Казахстан и остальные.

Номера с «+» разбираются сами. Записанные без кода страны — по региону
чата: `/region ID` в чате про Бали, и `0812…` прочтётся как индонезийский.
Глобальный запасной вариант — `DEFAULT_REGION` в `.env`.

Проверяются только длины обычных телефонов, мобильных и городских. Иначе
любой длинный набор цифр подходил бы под служебные номера: строка
`667653892134` превращалась в `+7 667653892134**`.

В странах с плавающей длиной номера (Индонезия — от 9 до 12 цифр без кода)
бот предупреждает, что номер мог потерять хвост: отличить обрезанный от
целого там невозможно.

## Два языка

Бот отвечает на языке того сообщения, на которое реагирует. В смешанной
группе русскому агенту ответит по-русски, англоязычному по-английски —
настраивать ничего не нужно. Язык определяется по алфавиту; если букв нет
вообще (прислали один номер), берётся `DEFAULT_LANG`. Прибить жёстко:
`/lang en`, снять: `/lang` без аргумента.

Тексты лежат таблицей на два языка в `texts.py`. Два теста следят за
полнотой: один сверяет наборы ключей, второй ищет кириллицу в английских
строках — забыть перевод нельзя.

## Настройка группы при подключении

Когда бота добавляют в чат или дают админа, он предлагает закрепить чат
за агентством и угадывает его из названия: совместные чаты почти всегда
называют «Агентство × Застройщик». Своё имя бот отбрасывает по
`DEVELOPER_NAME`, служебные слова — по списку. Заготовки вроде
«Agency name» отсеиваются.

Подтвердить может только администратор группы. После закрепления
агентство у участников не спрашивается — подставляется само. Привязка
чата важнее профиля агента: её задал админ осознанно.

## Когда сообщение считается фиксацией

Правила свободные: это рабочие чаты, сюда пишут ради клиентов. Имени и
телефона достаточно, слово «зафиксируйте» не обязательно. Даже один
номер без имени пройдёт — имя дописывается кнопкой.

Работает это потому, что запись всё равно идёт по кнопке: ложное
срабатывание стоит одного проигнорированного сообщения. Ключевое
различие — **чей номер**: клиентский ловим, номер отдела продаж, самого
агента или из рекламы игнорируем.

## Разорванные сообщения

Фиксацию часто пишут в два приёма: сначала номер, следом «зафиксируйте».
Бот помнит последние три сообщения каждого человека за десять минут и
передаёт их модели как контекст. Память раздельная по чатам и авторам.

## Справочник агентств

`Дом+`, `ООО "Дом Плюс"`, `АН ДОМ +`, `дом плюс` — это одно агентство.
Без нормализации в amoCRM за месяц появится 15 компаний вместо одной.

Бот срезает правовые формы (ООО, ИП, АН), приводит `плюс` → `+`, схлопывает
`ё` → `е`, чинит латинские буквы-двойники, и ищет похожие среди уже
известных. Новую компанию **не создаёт молча** — показывает кандидатов
кнопками и спрашивает.

Агентство определяется по приоритету: текст сообщения → привязка чата →
профиль агента.

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env      # заполнить
python bot.py
```

Подробная инструкция для Mac с нуля — в файле **ЗАПУСК-НА-MAC.md**.
Разбор логики и что будет дальше — в **ЛОГИКА-v2.md**.

### Обязательный шаг после запуска: разметка воронок

Без этого бот не отличит клиента отдела продаж от агентской фиксации
и будет отказываться работать. В личке с ботом:

```
/pipelines
```

Появится список воронок из твоей amoCRM с кнопками. Нажатие переключает тип
по кругу: не размечена → 🏢 розничная → 🤝 агентская → 🚫 не учитывать.

- **розничная** — клиенты отдела продаж, совпадение блокирует;
- **агентская** — фиксации от агентств, совпадение только предупреждает;
- **не учитывать** — воронка не участвует в проверке вообще.

Там же, в «🔧 Техническое», лежит раздел **«👤 Ответственный за фиксации»**:
список сотрудников из amoCRM, и выбранный ставится на каждую новую сделку
в момент создания. Не выбран — сделка достаётся владельцу токена, как
и было. Если менеджера уволили и amoCRM откажется принимать сделку, бот
создаст её без ответственного: терять фиксацию из-за кадровых перемен
нельзя.

## Команды

| Команда | Кто | Что делает |
|---|---|---|
| `/ping` | все | режим, куда кладёт фиксации, размер зеркала |
| `/check +7 999 123-45-**` | все | проверить номер, ничего не создавая |
| `/pipelines` | админ | разметка воронок кнопками |
| `/region ID` | админ | страна чата для номеров без кода |
| `/lang en` | админ | прибить язык чата; без аргумента — снять |
| `/bind Дом+` | админ | привязать текущий чат к агентству |
| `/sync` | админ | перевыгрузить базу amoCRM вручную |

## Что видит агент

Из ответов убраны любые упоминания CRM застройщика и ссылки на карточки:
у сторонних агентств доступа туда нет, для них это мусор. Включается
обратно через `SHOW_CRM_LINKS=1`.

Формулировки намеренно мягкие. Бот не знает договорённостей между
агентством и застройщиком, поэтому не выносит приговоров вроде «работать
нельзя», а сообщает факт и отправляет к менеджеру.

## Подключение к amoCRM

Два способа, переключаются через `AMO_AUTH`.

**Долгосрочный токен** (`long_lived`, по умолчанию) — Настройки →
Интеграции → своя интеграция → Ключи и доступы → выпустить долгосрочный
токен на срок до 5 лет. Работает локально, ничего обновлять не надо.

**OAuth** (`oauth`) — кнопка «Разрешить» в браузере. Нужен, только если
подключаются **чужие** аккаунты amoCRM. Требует публичного HTTPS-адреса
для `redirect_uri`, поэтому на локальном компьютере не заработает.
Access-токен живёт сутки и обновляется сам, refresh-токен — 3 месяца.

Код обоих способов в `amoauth.py`, там же инструкция по включению OAuth
и готовый сниппет кнопки авторизации. Вся остальная логика бота от способа
авторизации не зависит.

## Настройка правил распознавания

Правила — в **`prompts/fixation.md`**, обычным текстом. Файл перечитывается
на каждое сообщение, перезапуск не нужен.

Самое полезное — раздел «Примеры». Когда бот ошибся: скопируй сообщение
туда с правильным ответом. Десяток реальных примеров, включая
похожие-но-не-фиксации, работает лучше любых формулировок правил.

Для отладки поставь `QUIET=0` — бот начнёт объяснять, почему пропустил.

## Тесты

```bash
python -m pytest -q
```

192 теста: все вердикты и их приоритеты, граница года без активности,
маскированные номера пяти стран, отсев мусорных номеров, нормализация
названий агентств, разбор названия чата, определение языка и полнота
перевода, расчёт происхождения из сделок, подтверждение и права на него,
контекст соседних сообщений, миграции старой базы, отсутствие упоминаний
CRM в текстах.

Тесты нашли четыре бага, которые иначе выстрелили бы в бою: падение при
записи нового агента, склейку `+7` с уже полным номером, служебный этап
воронки, который amoCRM отказывается принимать, и потерю языка между
карточкой и подтверждением.

## Архитектура на будущее

Схема БД сразу рассчитана на несколько аккаунтов amoCRM: во всех таблицах
есть `account_id`. Пока аккаунт один, но когда подключатся чужие CRM —
структуру менять не придётся.

Что осталось на следующие этапы (см. ЛОГИКА-v2.md):

- **Этап 2**: реестр агентов, кнопка «Отслеживать статус», регистрация
  в личке через deep link, карточка клиента в личных сообщениях.
- **Этап 3**: уведомления о смене этапа сделки, оповещение конкурентов
  при выходе клиента на бронь, рассылки агентам с отпиской.
