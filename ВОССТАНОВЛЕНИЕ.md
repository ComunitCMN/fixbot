# Если сервер потерян

Сценарий на случай, когда сервера больше нет: не оплатили, отключили
аккаунт, отказал диск. Проверен на учебной тревоге — восстановление
на чистую машину с зашифрованной копии, данные сошлись до записи.

**Времени нужно минут двадцать.** Из них половина — установка пакетов.

## Что должно быть под рукой

1. **Пароль от копий** — тот, что в `BACKUP_PASSPHRASE`. Хранится
   в менеджере паролей, **не на сервере**. Без него копии бесполезны.
2. **Свежая копия** — приходит каждый день в Telegram файлом вида
   `fixbot-2026-07-30-0400.tar.gz.enc`. Скачайте последнюю.
3. **Доступ к GitHub** — код лежит там.

Больше ничего. Токены ботов, доступы к amoCRM, справочники агентств,
журнал фиксаций — всё внутри копии.

## Шаг 1. Новый сервер

Любой провайдер, Ubuntu 24.04, 2 ГБ памяти, **не в России** (иначе
Anthropic заблокирует адрес и бот останется без распознавания).

Зайдите по SSH и выполните:

```bash
apt update && apt install -y python3-venv python3-pip git sqlite3
adduser --disabled-password --gecos "" fixbot
mkdir -p /opt/fixbot/clients /opt/fixbot/backups
chown -R fixbot:fixbot /opt/fixbot
sudo -u fixbot ssh-keygen -t ed25519 -f /home/fixbot/.ssh/id_ed25519 -N "" -q
cat /home/fixbot/.ssh/id_ed25519.pub
```

Ключ из последней строки добавьте в GitHub: репозиторий → Settings →
Deploy keys → Add deploy key, **без** права записи.

## Шаг 2. Код

```bash
sudo -u fixbot bash <<'EOF'
set -e
ssh-keyscan -t ed25519 github.com >> ~/.ssh/known_hosts 2>/dev/null
git clone git@github.com:ComunitCMN/fixbot.git /opt/fixbot/app
cd /opt/fixbot/app
python3 -m venv venv
./venv/bin/pip install -q -r requirements.txt
./venv/bin/python -m pytest -q | tail -2
EOF
```

Тесты должны пройти полностью. Не прошли — не продолжайте, разбирайтесь
с причиной: дальше пойдут боевые данные.

## Шаг 3. Данные

Скопируйте архив из Telegram на сервер (или скачайте на компьютер
и отправьте через `scp`), затем:

```bash
/opt/fixbot/app/restore-on-server.sh /root/fixbot-2026-07-30-0400.tar.gz.enc
```

Спросит пароль. Дальше сам разложит настройки и базы по местам
и **перепишет пути внутри** — на старом сервере они могли быть другими.

Сверьте числа: скрипт печатает, сколько фиксаций в каждой базе. Они
должны совпасть с подписью к архиву в Telegram.

## Шаг 4. Службы

Возьмите готовые куски из `СЕРВЕР.md`, разделы «Служба systemd»
и «Права для помощника подключения». Потом:

```bash
systemctl enable --now fixbot-operator
for d in /opt/fixbot/clients/*/; do
    systemctl enable --now "fixbot@$(basename "$d")"
done
systemctl is-active fixbot-operator 'fixbot@*'
```

## Шаг 5. Проверка

```bash
tail -5 /opt/fixbot/app/bot.log
```

Ищем `Start polling`. Потом напишите боту `/admin` в Telegram.

Группы переподключать не нужно: токены те же, чаты бота помнят.

**Если старый сервер ещё жив** — сначала выключите на нём службы.
Два экземпляра с одним токеном начнут перехватывать сообщения друг
у друга.

## Шаг 6. Вернуть копии

Новый сервер копий пока не делает. Поднимите расписание по `СЕРВЕР.md`,
раздел «Резервные копии», и дождитесь первого архива в Telegram.

Пока он не пришёл — вы снова в одном экземпляре.

## Чего этот сценарий не покрывает

**Потерян пароль от копий.** Восстановить нечего. Пароль должен лежать
в менеджере паролей, отдельно от сервера и отдельно от Telegram.

**Взломан аккаунт Telegram.** Копии зашифрованы, но злоумышленник
получит доступ к боту-оператору. Включите двухфакторную защиту
в Telegram — это единственная дверь к управлению всеми клиентами.
