# FixBot v2 — агентства, агенты, уведомления

Разбор перед тем, как писать код. Читать сверху вниз, в конце — вопросы,
на которые нужны твои ответы.

---

## Принятые решения

| Вопрос | Решение |
|---|---|
| Чей клиент | по **воронке** сделки: розничная → собственный, агентская → агентская фиксация |
| Эксклюзив у агентства | **нет**, несколько агентств ведут клиента параллельно, кто первый на бронь |
| Клиент отдела продаж | блокирует; освобождается после **года без активности** |
| Ответ при чужой фиксации | обезличенно, **только дата**, без названия агентства |
| Срок агентской фиксации | не ограничен (эксклюзива нет — ограничивать нечего) |

Открытым остаётся только состав уведомлений по этапам воронки —
решается настройкой, а не кодом (см. ниже).

---

## Что добавляем

1. **Агентство** — каждая фиксация привязывается к агентству, агентство
   записывается в Компанию в amoCRM.
2. **Реестр агентов** — бот знает, кто из Telegram прислал фиксацию, и умеет
   писать этому человеку в личку.
3. **Уведомления и рассылки** — статус клиента прилетает агенту в личку,
   плюс возможность разослать всем агентам объявление.

## Блок 1. Агентство

### Откуда бот узнаёт агентство

Четыре источника, в порядке приоритета:

| # | Источник | Когда срабатывает | Надёжность |
|---|---|---|---|
| 1 | Из текста сообщения | «Агентство: Дом+» — LLM извлекает | средняя, зависит от дисциплины |
| 2 | Профиль агента | агент один раз указал в личке | **высокая** |
| 3 | Привязка чата | один чат = одно агентство | высокая, если так устроено |
| 4 | Не определено | бот отвечает и просит уточнить | — |

Логика: сначала пробуем текст, если пусто — берём из профиля агента, если
и там пусто — смотрим привязку чата, если ничего — переспрашиваем.

### Проблема, из-за которой всё может развалиться

Одно и то же агентство пишется по-разному: `Дом+`, `дом плюс`, `ДОМ +`,
`АН Дом+`, `Дом Плюс ООО`. Если создавать компанию в amoCRM «как написано»,
через месяц там будет 15 карточек вместо одной, и вся аналитика по агентствам
превратится в кашу.

Решение — **справочник агентств** в боте:

1. Компании из amoCRM выгружаются в локальное зеркало (как сейчас телефоны).
2. Пришедшее название нормализуется: убираются `ООО`, `АН`, `ИП`, кавычки,
   лишние пробелы, всё в нижний регистр → `дом+`.
3. Ищется похожая существующая компания (нечёткое сравнение).
4. Нашли — используем её. Не нашли — **не создаём молча**, а спрашиваем:
   «Не нашёл агентство "Дом Плюс ООО". Это [Дом+] или [создать новое]?»
   с кнопками.

Это чуть больше работы, но без этого справочник загадится за пару недель.

### Как ложится в amoCRM

```
Компания «Дом+»  ──┐
                   ├── Сделка «Петров Сергей — ЖК Восход»
Контакт «Петров» ──┘         поле «Агент»: @ivan_petrov
                             поле «Дата фиксации»: 27.07.2026
                             поле «Фиксация до»: 25.10.2026
                             тег: telegram-фиксация
```

- **Компания** = агентство. Ищется по справочнику, создаётся только при
  подтверждении.
- **Контакт** = клиент. Привязывается к сделке.
- **Сделка** связывает клиента, агентство и параметры фиксации.

Спорный момент: привязывать ли контакт-клиента напрямую к компании-агентству.
Плюс — в карточке агентства видно всех его клиентов. Минус — поле «Компания»
у клиента будет означать не «где он работает», а «кто его привёл», и это
может путать менеджеров. Вынес в вопросы.

## Блок 2. Агенты и личка

### Главное ограничение Telegram

**Бот не может написать человеку первым.** Пока агент сам не нажал Start
в личном чате с ботом — никаких уведомлений и рассылок ему не отправить.
Обойти нельзя, это на стороне Telegram.

Поэтому нужен момент, в который агенту выгодно подписаться. Он есть:
агенту важно знать судьбу своего клиента.

### Как выглядит подписка

Агент пишет фиксацию в группе → бот отвечает и добавляет кнопку:

```
🟢 Клиент уникальный — зафиксирован
Петров Сергей — +7 916 445-22-**
Агентство: Дом+  ·  Агент: Иван Петров

[ 🔔 Отслеживать статус клиента ]   ← кнопка-ссылка
```

Кнопка ведёт на `t.me/твой_бот?start=fix_412`. Агент тапает → открывается
личка → жмёт Start → бот получает код `fix_412`, понимает, о какой фиксации
речь, и связывает её с этим человеком.

**Защита:** бот проверяет, что нажавший Start — тот же Telegram-аккаунт,
который отправил фиксацию в группу. Иначе чужие фиксации мог бы отслеживать
кто угодно.

### Первый диалог в личке

```
Бот: Привет, Иван! Вы отслеживаете фиксацию:
     Петров Сергей, +7 916 445-22-**, ЖК Восход
     Статус: активна до 25.10.2026

     Из какого вы агентства?
     [ Дом+ ]  [ Новосёл ]  [ Этажи ]  [ Другое ]
```

Агентство спрашивается один раз. Дальше все его фиксации автоматически
подписываются нужным агентством, даже если в сообщении он его не указал.
Это заодно чинит проблему из Блока 1.

После этого бот знает: Telegram ID, имя, username, агентство, и что личка
открыта. Этого достаточно для рассылок.

### Если агент подписан заранее

Тогда кнопки нет, а в ответе в группе пишется просто:
«Статус отправлен вам в личные сообщения». И бот сразу дублирует карточку
клиента в личку.

### Кто не сможет подписаться

- Сообщения от анонимных админов и от имени канала — Telegram не отдаёт
  автора. Бот ответит: «не вижу, кто отправил, напишите от своего имени».
- Агенты без username — не проблема, ID есть всегда.

## Блок 3. Уведомления и рассылки

### Уведомления о статусе клиента

Задача: сделка в amoCRM переехала в «Встреча назначена» → агент получает
сообщение в личку.

Два способа получать эти события:

| | Опрос (polling) | Вебхуки |
|---|---|---|
| Как | бот раз в 5-10 мин спрашивает amoCRM о своих сделках | amoCRM сама стучится к боту при изменении |
| Задержка | до 10 минут | мгновенно |
| Нужен сервер с доменом и HTTPS | **нет** | **да** |
| Работает на твоём Mac | да | нет |
| Сложность | простая | средняя |

Для старта — опрос. Задержка в 10 минут для «клиенту назначили встречу»
роли не играет, зато не требует сервера. Вебхуки можно включить потом,
код меняется в одном месте.

### Про какие события уведомлять

Черновой список, правится под твою воронку:

- сделка сменила этап («В работе» → «Встреча» → «Бронь» → «Договор»)
- сделка закрыта успешно → поздравление и, если надо, сумма комиссии
- сделка закрыта с отказом → причина
- **фиксация истекает через 7 дней** → «клиент скоро освободится, продлить?»
- **фиксация истекла** → клиент снова доступен для фиксации другими

Последние два — не из amoCRM, а по таймеру самого бота.

### Рассылки

```
/broadcast              — начать рассылку (только для админов)
  → бот спрашивает текст
  → спрашивает кому: [всем] [агентству X] [только активным за 30 дней]
  → показывает превью и число получателей
  → [Отправить] [Отмена]
```

Технические моменты, которые надо учесть:

- Telegram ограничивает скорость — отправка идёт пачками, ~20 сообщений
  в секунду с паузами. Рассылка на 500 агентов займёт около минуты.
- Если агент заблокировал бота, отправка вернёт ошибку — такого агента
  помечаем и больше не тревожим.
- В конце админ получает отчёт: доставлено / заблокировали / ошибки.
- **Нужна отписка.** Команда `/stop` в личке. Без неё люди просто
  заблокируют бота, и ты потеряешь и рассылки, и уведомления по клиентам.
  Лучше сделать раздельно: отписка от рассылок ≠ отписка от статусов
  своих клиентов.

## Блок 0. Главное: чей это клиент

Это ядро всей логики, и оно устроено НЕ как «нашли совпадение → отказ».

**Агентская фиксация не даёт эксклюзива.** Несколько агентств могут вести
одного клиента одновременно. Кто первый привёл на бронь — тот и получил.
Поэтому при совпадении с другой агентской фиксацией бот **всё равно
фиксирует клиента** и просто предупреждает, что он не один такой.

**Клиент отдела продаж — стоп.** Если человек уже в базе застройщика
(пришёл по рекламе, звонком, с сайта, был заведён менеджером) — он не
уникальный, агентству с ним работать нельзя. Тут бот отказывает.

То есть решение зависит не от факта совпадения, а от **происхождения
записи** в amoCRM.

### Как бот определяет происхождение

Решено: **по воронке сделки**. По приоритету:

| # | Признак | Вывод |
|---|---|---|
| 1 | Есть сделка в розничной воронке, активность < года | **собственный клиент** — блокируем |
| 2 | Есть сделка в розничной воронке, активность > года | клиент освободился — **фиксируем**, но помечаем |
| 3 | Сделка только в агентской воронке | агентская фиксация — фиксируем с предупреждением |
| 4 | Контакт без сделок вообще | **считаем собственным**, помечаем как спорный |

Четвёртая строка — осознанно консервативная. Ошибка «зря пропустили»
стоит застройщику комиссии за собственного клиента, ошибка «зря
заблокировали» стоит одного разбора вручную. Второе дешевле.

Но глухо отказывать при неясности тоже плохо, поэтому в этом случае ответ
не красный, а жёлтый: «клиент найден в базе, происхождение не определено,
уточните у менеджера» — и тебе прилетает уведомление на разбор.

### Что считать «активностью»

Год отсчитывается от последнего из событий по связанным розничным сделкам:
изменение сделки, смена этапа, новая задача или примечание. В amoCRM это
поле `updated_at` у сделки. Если сделок нет — от даты создания контакта.

### Настройка воронок

Какая воронка розничная, а какая агентская, бот узнаёт не из кода,
а из настройки. Команда `/pipelines` в личке админа покажет список воронок
из твоей amoCRM с кнопками — отметишь, какая есть какая. Там же выберешь,
о каких этапах уведомлять агентов и какой этап считается бронью.

Это удобнее, чем прописывать ID руками, и переживает переименование
воронок в CRM.

## Как меняется ответ бота при совпадении

Пять сценариев вместо прежних трёх:

**1. Совпадений нет**
> 🟢 Клиент уникальный — зафиксирован за агентством Дом+
> [ 🔔 Отслеживать статус ]

**2. Тот же агент повторно**
> ℹ️ Вы уже фиксировали этого клиента 12 дней назад, 15.07.2026.
> Повторно фиксировать не нужно.

**3. Коллега из того же агентства**
> ℹ️ Клиента уже зафиксировал ваш коллега Иван Петров 15.07.2026.
> Фиксация числится за Дом+.

**4. Есть фиксация другого агентства — работать можно**
> 🟡 Клиент зафиксирован — но не только вами.
> По этому номеру уже есть фиксация другого агентства от 15.07.2026.
> Эксклюзива нет: клиент достаётся тому, кто первым доведёт до брони.
> [ 🔔 Отслеживать статус ]

Клиент при этом фиксируется как обычно, сделка создаётся.
Название агентства-конкурента не раскрывается — только дата.

**5. Клиент отдела продаж — отказ**
> 🔴 Клиент НЕ уникальный.
> Он уже в работе у отдела продаж, последняя активность 03.06.2026.
> Работа по агентской схеме невозможна.

Сделка не создаётся, попытка логируется.

**6. Клиент отдела продаж, но больше года без движения**
> 🟢 Клиент был в базе отдела продаж, но без активности с 10.05.2025.
> Срок истёк — фиксирую за вами.
> [ 🔔 Отслеживать статус ]

Тебе при этом прилетает уведомление: «агентство забрало остывшего
клиента отдела продаж» — на случай, если менеджер как раз собирался
его реанимировать.

**7. Происхождение неясно**
> 🟡 Клиент найден в базе, но не удалось определить, чей он.
> Отправил на проверку менеджеру, ответ придёт в течение дня.

### Отдельно: бронь закрывает конкуренцию

Как только один из конкурирующих агентов доводит клиента до брони,
остальные должны это увидеть. Иначе они продолжат вкладываться
в заведомо проигранного клиента.

Предлагаю: при переходе сделки в статус брони бот автоматически
уведомляет всех остальных агентов, фиксировавших этого же клиента:
«клиент вышел на бронь с другим агентством, работа по нему закрыта».
Заодно это сильный аргумент для агентов подписаться на бота.

## Ограничения, о которых стоит знать заранее

1. **Бот не пишет первым** — пока агент не нажал Start, уведомлений не будет.
   Это не баг, это Telegram.
2. **Мгновенные уведомления требуют сервера** с доменом и HTTPS. На Mac
   будет работать вариант с опросом раз в 5-10 минут.
3. **Рассылки без отписки убивают базу.** Люди блокируют бота, и вместе
   с рассылками теряются уведомления по клиентам.
4. **Названия агентств надо приводить к справочнику**, иначе аналитика
   по агентствам развалится за месяц.
5. **Срок фиксации — центральное понятие.** Без него не работает
   освобождение клиентов и напоминания.

## Решено по умолчанию

Мелочи, которые я закрыл сам, чтобы не тормозить. Любую можно переиграть.

- **Источник агентства**: приоритет — профиль агента (указал один раз
  в личке), потом текст сообщения, потом привязка чата. Профиль первым,
  потому что он единственный не зависит от дисциплины при написании.
- **Связь в amoCRM**: агентство привязывается к сделке, к контакту-клиенту
  не привязывается. Поле «Компания» у клиента остаётся под его реальное
  место работы и не путает менеджеров.
- **Рассылки**: только для ID из `ADMIN_IDS`, с обязательным превью
  и подтверждением перед отправкой.
- **Отписка**: `/stop` отключает рассылки, но НЕ отключает уведомления
  по собственным клиентам агента. Это разные вещи, смешивать нельзя.

## Порядок работ

Делить на три захода, каждый работает сам по себе:

**Этап 1 — агентства и происхождение** (ядро, без него остальное бессмысленно)
- справочник агентств с нормализацией названий
- зеркало компаний и воронок из amoCRM
- команда `/pipelines` для настройки розничной и агентской воронок
- новая логика семи сценариев ответа
- компания-агентство на сделке

**Этап 2 — агенты и личка**
- реестр агентов, кнопка «Отслеживать статус», deep link
- регистрация в личке с выбором агентства
- карточка клиента в личку, команда «мои фиксации»

**Этап 3 — уведомления и рассылки**
- опрос amoCRM раз в 5–10 минут, отслеживание смены этапа
- уведомление конкурентам при выходе клиента на бронь
- `/broadcast` с превью, троттлингом и отчётом
- `/stop` и обработка блокировок

После Этапа 1 бот уже полезен: перестанет отдавать агентствам клиентов
отдела продаж. Это, судя по всему, главная боль.
