# Как подключить нового застройщика

Чек-лист для оператора. Всё техническое делаешь ты, от клиента нужно три вещи.

---

## Что попросить у клиента заранее

Отправь ему файл **ДЛЯ-КЛИЕНТА.md** и попроси прислать:

1. **Ключ бота** — он создаёт бота у @BotFather, строка вида
   `7123456789:AAF-xxxxx`
2. **Свой Telegram ID** — узнаёт у @userinfobot, число вида `141904174`
3. **Доступ к amoCRM** — долгосрочный токен интеграции (см. ниже)

Заодно проверь, что он **выключил Group Privacy** у бота. Без этого
ничего не заработает, а понять причину со стороны невозможно.

### Про доступ к amoCRM — самое узкое место

Токен может выпустить только **администратор его аккаунта** amoCRM.
Это единственное, что нельзя сделать за него.

Варианты:

- он сам админ — присылает токен, всё просто;
- админ кто-то другой — нужно, чтобы этот человек выпустил токен;
- никто не хочет возиться — тогда OAuth с кнопкой «Разрешить», но для
  этого нужен сервер с доменом и HTTPS. Код готов, см. `amoauth.py`.

Инструкция для него: Настройки → Интеграции → Создать интеграцию →
Внешняя интеграция → права → сохранить → вкладка «Ключи и доступы» →
выпустить долгосрочный токен на 5 лет. Плюс поддомен: если заходит
на `https://romashka.amocrm.ru`, то поддомен — `romashka`.

### Какие права нужны

| Сущность | Права |
|---|---|
| Сделки | просмотр, создание, редактирование |
| Контакты | просмотр, создание, редактирование |
| Компании | просмотр, создание, редактирование |

Удаление не нужно нигде — бот ничего не удаляет. Покупатели, задачи,
списки, почта, аналитика, файлы и настройки тоже не нужны.

**Область доступа — «Все», а не «Только свои».** Это легко пропустить,
а последствие неприятное: API отдаст лишь ту часть базы, что принадлежит
одному пользователю, и бот будет считать чужих клиентов новыми. Заодно
проверьте, что интеграция видит все воронки, а не отдельные.

Признак, что права урезаны: в «Состоянии» подозрительно мало сделок
относительно числа контактов.

## Шаг 1. Реши, где запускать

**Быстро, на своём маке.** Годится, чтобы показать клиенту сегодня.
Минус тот же, что у тебя: бот живёт, пока открыт Терминал, и умирает
вместе со сном ноутбука.

**Правильно, на сервере.** VPS за 300–500 ₽ в месяц, бот работает
круглосуточно и переживает перезагрузки. Разворачивание по `СЕРВЕР.md`,
примерно час.

Дальше шаги одинаковые, отличается только папка.

---

## Шаг 2. Сделай папку клиента

**Проще всего — помощником подключения.** «🗂 Мои клиенты» → «➕ Новый
клиент» → отправь ссылку клиенту. Он пройдёт пять шагов, ты получишь
заявку с кнопкой «🚀 Развернуть», и папка с настройками создастся сама.
Тогда шаги 2–3 можно пропустить.

Один раз нужно сказать боту, где держать клиентов. В `~/Desktop/fixbot/.env`:

```
CLIENTS_DIR=/Users/ИМЯ/Desktop/clients
```

На сервере — `/opt/fixbot/clients`. Без этой строки кнопка «Развернуть»
откажется работать: ей некуда класть папку.

**Руками**, если помощник почему-то не подходит:

```bash
mkdir -p ~/Desktop/clients/friend
cp ~/Desktop/fixbot/.env.example ~/Desktop/clients/friend/.env
open -e ~/Desktop/clients/friend/.env
```

Код не копируй: он общий, у каждого клиента только свои настройки и база.

---

## Шаг 3. Заполни настройки

```
TELEGRAM_TOKEN=       # ключ бота клиента
ANTHROPIC_API_KEY=    # можно твой, один на всех
AMO_SUBDOMAIN=        # поддомен его amoCRM
AMO_LONG_TOKEN=       # его долгосрочный токен
DEVELOPER_NAME=       # название его компании
OPERATOR_IDS=         # твой Telegram ID
OWNER_IDS=            # его Telegram ID
DB_PATH=/полный/путь/к/clients/friend/fixbot.db
DRY_RUN=1             # первую неделю в режиме наблюдения
```

`DEVELOPER_NAME` нужен, чтобы бот вычленял агентство из названий чатов:
из «TEUS & BREIG» он отбросит BREIG и предложит TEUS.

`DB_PATH` обязательно с полным путём и своим именем папки — иначе клиенты
начнут писать в одну базу.

---

## Шаг 4. Запусти

На маке — в **новом** окне Терминала (`Cmd+N`), тем, где крутится
`run.sh`, пользоваться нельзя, оно занято логами:

```bash
cd ~/Desktop/fixbot
./run-client.sh friend
```

Скрипт сам найдёт папку клиента, подхватит его настройки и будет
перезапускать бота, если тот упадёт. Логи пишутся в
`~/Desktop/clients/friend/bot.log`. Остановить — `Ctrl+C`.

Каждому клиенту нужно своё окно: это отдельные боты с отдельными базами.

На сервере:

```bash
sudo systemctl enable --now fixbot@friend
tail -f /opt/fixbot/clients/friend/bot.log
```

Ждём в логе `Start polling`. Первая синхронизация выкачает его базу
amoCRM — может занять несколько минут.

---

## Шаг 5. Размести воронки

Это обязательный шаг, без него бот работать откажется.

Напиши **его боту** в личку `/admin` → **🔧 Техническое** →
**Разметка воронок**. Дальше кнопками:

- 🏢 **розничная** — воронки отдела продаж. Совпадение с ними блокирует
  агентскую фиксацию;
- 🤝 **агентская** — куда бот кладёт свои фиксации;
- 🚫 **не учитывать** — воронка не участвует в проверке.

**Если агентской воронки у клиента нет — её надо создать.** Попроси его
завести в amoCRM воронку «Агентские фиксации» с этапами вроде
«Фиксация → Показ → Бронь → Договор». Без неё сделки бота попадут
в розничную воронку, и через неделю он начнёт блокировать собственные
же фиксации как «клиентов отдела продаж».

После создания: **🔧 Техническое** → **Синхронизировать**, потом снова
разметка — новая воронка появится в списке.

---

## Шаг 6. Проверь на живых данных

В личке с ботом:

```
/check +7 XXX XXX-XX-XX
```

Возьми настоящий номер клиента из его розничной воронки. Ответ должен
быть 🔴 «клиент не уникальный, зафиксирован за прямым отделом продаж».
Если так — главная механика работает.

Потом проверь маскированный номер того же клиента, закрыв две последние
цифры звёздочками. Тоже должно быть 🔴.

**🔧 Техническое → Состояние** покажет сводку: режим, куда кладёт
фиксации, размечены ли воронки, сколько телефонов в зеркале.

---

## Шаг 7. Отдай клиенту

Напиши ему, что всё готово, и передай **ДЛЯ-КЛИЕНТА.md**. Скажи:

1. напиши боту `/admin` — откроется меню;
2. добавь бота в группу с первым агентством и **сделай администратором**;
3. бот сам предложит закрепить группу за агентством.

Дальше он справится сам. Раздела «Техническое» у него не будет.

---

## Шаг 8. Первая неделя в режиме наблюдения

`DRY_RUN=1` уже стоит: бот отвечает в чатах, но в CRM ничего не пишет.
Это нужно, чтобы поймать промахи распознавания на его формулировках,
не насорив в базе.

Попроси клиента присылать примеры, где бот ошибся — пропустил фиксацию
или среагировал на лишнее. Правила лежат в `prompts/fixation.md`
обычным текстом, файл перечитывается на каждое сообщение, перезапуск
не нужен. Добавляешь пример в раздел «Примеры» — точность растёт.

Когда промахов не останется, поставь `DRY_RUN=0` и перезапусти.

---

## Быстрая сводка

| Кто | Что делает |
|---|---|
| Клиент | Создаёт бота, выключает Privacy Mode, присылает ключ и свой ID |
| Клиент | Даёт токен amoCRM (нужны админские права в его аккаунте) |
| Клиент | Заводит агентскую воронку, если её нет |
| Ты | Папка, настройки, запуск |
| Ты | Размечаешь воронки, проверяешь на живом номере |
| Ты | Отдаёшь ДЛЯ-КЛИЕНТА.md |
| Клиент | Подключает группы с агентствами |
| Оба | Неделя наблюдения, донастройка правил |

## Что может пойти не так

**Бот молчит в группе.** Не администратор или включён Privacy Mode.
После выключения Privacy Mode бота надо удалить из группы и добавить
заново.

**`401` или `403` от amoCRM.** Токен неполный (он очень длинный, легко
обрезать при копировании) или у интеграции нет прав на сделки, контакты
и компании.

**Бот отвечает «некуда класть фиксацию».** Не размечена агентская воронка,
см. шаг 5.

**Клиент не видит `/admin`.** Его ID не попал в `OWNER_IDS` или в файле
опечатка. Проверь и перезапусти.

**Два бота дерутся за одну очередь.** Если в логе `ConflictError` —
запущено два экземпляра с одним токеном. Останови лишний.
