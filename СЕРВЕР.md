# Несколько клиентов на одном сервере

Ты держишь бота у себя, клиенты только пользуются. Каждый застройщик —
отдельный экземпляр: свой токен бота, свои настройки, своя база.

## Почему не один процесс на всех

В схеме базы есть `account_id`, и технически можно было бы обслуживать всех
одним процессом. Но отдельные экземпляры надёжнее:

- данные клиентов физически не смешиваются, утечка между ними невозможна;
- ошибка у одного не роняет остальных;
- любого можно перезапустить, обновить или остановить отдельно;
- у каждого свой токен бота — а один процесс с несколькими токенами
  требует отдельного цикла опроса на каждого, и это лишняя сложность.

Цена — несколько десятков мегабайт памяти на клиента. На копеечном VPS
спокойно живёт десяток.

## Раскладка

```
/opt/fixbot/
├── app/                  ← код, один на всех, обновляется git pull
│   ├── bot.py
│   ├── requirements.txt
│   └── venv/
└── clients/
    ├── breig/
    │   ├── .env          ← токен бота, ключи, роли
    │   └── fixbot.db     ← база этого клиента
    └── friend/
        ├── .env
        └── fixbot.db
```

Код общий, данные раздельные. Каждый клиент запускается службой
`fixbot@breig`, `fixbot@friend` — с указанием своей папки.

## Установка

```bash
# зависимости системы
sudo apt update && sudo apt install -y python3-venv git

# код
sudo mkdir -p /opt/fixbot && cd /opt/fixbot
sudo git clone <адрес-репозитория> app
cd app
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

## Права для помощника подключения

Бот умеет разворачивать нового клиента сам — по кнопке «Развернуть».
Для этого ему нужно право запускать службы своего шаблона, и только их.
Полный sudo давать не надо.

```bash
sudo tee /etc/sudoers.d/fixbot > /dev/null <<'EOF'
fixbot ALL=(root) NOPASSWD: /bin/systemctl enable --now fixbot@*, \
                            /bin/systemctl restart fixbot@*, \
                            /bin/systemctl stop fixbot@*, \
                            /bin/systemctl is-active fixbot@*
EOF
sudo chmod 440 /etc/sudoers.d/fixbot
```

Замените `fixbot` на пользователя, под которым работает бот. Никаких
других прав не требуется: ни установки пакетов, ни доступа к чужим файлам.

Проверить:

```bash
sudo -n systemctl is-active fixbot@breig
```

Если отвечает без запроса пароля — права выданы верно.

## Новый клиент вручную

Обычно этого делать не нужно — есть помощник подключения: в меню
«🗂 Мои клиенты» → «➕ Новый клиент» → отправляете клиенту ссылку,
он проходит пять шагов, вы жмёте «Развернуть». Ниже — как то же самое
сделать руками, если помощник почему-то не подходит.

```bash
mkdir -p /opt/fixbot/clients/friend
cp /opt/fixbot/app/.env.example /opt/fixbot/clients/friend/.env
nano /opt/fixbot/clients/friend/.env
```

Что обязательно заполнить:

```
TELEGRAM_TOKEN=        # токен бота, который создал клиент
ANTHROPIC_API_KEY=     # можно один на всех клиентов
AMO_SUBDOMAIN=         # поддомен amoCRM клиента
AMO_LONG_TOKEN=        # долгосрочный токен его интеграции
DEVELOPER_NAME=        # название застройщика
OPERATOR_IDS=          # твой Telegram ID
OWNER_IDS=             # Telegram ID клиента
DB_PATH=/opt/fixbot/clients/friend/fixbot.db
```

`OPERATOR_IDS` — ты, видишь техническое. `OWNER_IDS` — клиент, видит
рассылки, группы, агентства и статистику. Сотрудников клиент добавляет
сам через меню, тебе приходит уведомление.

## Служба systemd

Один файл-шаблон на всех клиентов:

```bash
sudo tee /etc/systemd/system/fixbot@.service > /dev/null <<'EOF'
[Unit]
Description=FixBot (%i)
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/fixbot/clients/%i
EnvironmentFile=/opt/fixbot/clients/%i/.env
ExecStart=/opt/fixbot/app/venv/bin/python /opt/fixbot/app/bot.py
Restart=always
RestartSec=10
StandardOutput=append:/opt/fixbot/clients/%i/bot.log
StandardError=append:/opt/fixbot/clients/%i/bot.log

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
```

Дальше на каждого клиента:

```bash
sudo systemctl enable --now fixbot@friend
```

`Restart=always` поднимает бота после падения, `enable` — после
перезагрузки сервера. Именно этого не хватало на ноутбуке.

## Повседневное

```bash
# состояние
systemctl status fixbot@friend

# логи в реальном времени
tail -f /opt/fixbot/clients/friend/bot.log

# перезапуск одного клиента
sudo systemctl restart fixbot@friend

# обновить код у всех
cd /opt/fixbot/app && git pull
./venv/bin/pip install -r requirements.txt
sudo systemctl restart 'fixbot@*'
```

## Резервные копии

Вся ценность в файлах `fixbot.db`: справочник агентств, реестр агентов,
журнал фиксаций, привязки чатов. Сами фиксации лежат ещё и в amoCRM,
но привязки и агентов оттуда не восстановить.

```bash
sudo tee /etc/cron.daily/fixbot-backup > /dev/null <<'EOF'
#!/bin/bash
d=/opt/fixbot/backups/$(date +%F)
mkdir -p "$d"
for f in /opt/fixbot/clients/*/fixbot.db; do
    name=$(basename "$(dirname "$f")")
    sqlite3 "$f" ".backup '$d/$name.db'"
done
find /opt/fixbot/backups -maxdepth 1 -type d -mtime +30 -exec rm -rf {} +
EOF
sudo chmod +x /etc/cron.daily/fixbot-backup
```

Копия делается через `.backup`, а не обычным копированием: база работает
в режиме WAL, и файл на ходу можно поймать в несогласованном виде.

## Что стоит помнить

**Ключ Claude общий.** Можно один на всех клиентов — расход считается
по сообщениям, а не по ботам. Но тогда счёт общий: если хочешь выставлять
клиентам отдельно, заведи им отдельные ключи.

**amoCRM у каждого своя.** Токен клиента лежит только в его `.env`.
Клиент этот токен не видит и в меню бота до него не доберётся.

**Один бот — один застройщик.** Разделять клиентов внутри одного бота
нельзя: агенты из разных агентств попадут в чужие чаты.

**OAuth вместо токена.** Когда захочешь подключать чужие amoCRM кнопкой
«Разрешить», понадобится домен с HTTPS и обратный прокси. Код уже готов,
переключается через `AMO_AUTH=oauth`, подробности в `amoauth.py`.
